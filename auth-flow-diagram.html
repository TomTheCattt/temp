Key Implementation Details

Refresh Token Mechanism (Local Backend)

  • No backend refresh token endpoint used — the local backend doesn't issue its own refresh token (the POST /v1/auth/refresh endpoint exists but isn't called)
  • Firebase ID token IS the access token — both configs use Firebase's ID token (JWT, ~1hr expiry) as the Bearer token for all API calls
  • Firebase SDK handles rotation — user.getIDToken() automatically refreshes if expired; we just call it
  • Expiry extracted from JWT — FirebaseAuthService.extractExpiryFromToken() decodes the exp claim from the JWT payload
  • Proactive refresh — AuthManager.refreshTokenIfNeeded() checks if token expires within 5 minutes and refreshes preemptively
  • Interceptor-based retry — AuthInterceptor catches 401, calls refreshToken(), retries once

Dual Backend Configuration

// RepositoryAssembly.swift
let useRemote = AppConfig.shared.useLocalBackend || AppConfig.shared.isLiveAPI

container.register(AuthRepositoryProtocol.self) { resolver in
    if useRemote {
        return AuthRepository(
            remoteDataSource: RemoteAuthDataSource(
                networkService: resolver.resolve(NetworkServiceProtocol.self)!
            )
        )
    }
    return FirebaseAuthRepository()  // Firebase production
}
